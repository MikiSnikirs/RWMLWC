# Архитектура

Статус: согласовано 14.11.2026. Изменения вносятся через запись в `AGENT_LOG.md`.

## 1. Платформа

- RimWorld 1.7.5005, движок Waylith, .NET 10 (CoreCLR), Vulkan.
- `UnityEngine*` перенаправляется в `UnityStubs.dll`.
- Harmony 3.
- В рантайме есть инъекция полей и заглушка Prepatcher (`RimWorldWaylith.PrepatcherCompat.dll`). Можно ли добавлять поля без зависимости от Prepatcher — не проверено (задача T-004).
- Флаг `MonoStringHashCode` включён: хеши строк стабильны между машинами.
- Использует ли симуляция потоки — не проверено (задача T-003). Для lockstep это критично.
- В комплекте игры Steamworks.NET и `msquic.dll`.

## 2. Модель синхронизации: «владелец карты — авторитет»

1. **Lockstep только на общей карте.** Когда на карте два игрока, синхронизируются их команды, симуляция идёт у обоих.
2. **Раздельные поселения считает владелец.** Второй клиент чужую карту не симулирует.
3. **Переключение на поселение друга.** Владелец отдаёт снимок карты, гость входит в сессию этой карты с выданными правами.
4. **Десинк лечится.** По каждой карте считается хеш состояния. При расхождении владелец пересылает только эту карту.
5. **Перехват ввода на уровне UI.** Гизмо, контекстные меню, дезигнаторы, диалоги ловятся общим механизмом, а не разметкой каждого метода. Это основа совместимости с модами.
6. **Мир синхронизируется событиями.** Караваны, торговля, новые поселения.

## 3. Время

- Один общий счётчик тиков на весь мир.
- Игра идёт на **меньшей** из скоростей, выбранных игроками. Пауза любого останавливает всех.
- На паузе приказы и разметка принимаются.
- При бое на любой карте скорость не выше 1x, пока владелец карты не снимет ограничение.

## 4. Неактивный игрок

**В сети, но отошёл:**

- нет ввода N минут → игрок неактивен, его выбор скорости не учитывается;
- серьёзное событие на его карте → глобальная пауза 30–60 с и звуковой сигнал; нет отклика → режим отсутствия.

**Не в игре:** авторитет над картой передаётся оставшемуся игроку (снимок при выходе и периодически вместе с автосохранением).

Режимы отсутствия, выбирает владелец заранее. По умолчанию — **Стазис**:

| Режим | Поведение |
|---|---|
| Автопилот | Пешки живут по расписанию и приоритетам. |
| Управляющий | То же, друг получает заранее выданные права. |
| Стазис | Карта не тикает. |

**Угрозы без владельца:** крупные угрозы (рейды, осады, нашествия, кластеры мехов, события Anomaly) на карту отсутствующего не приходят ни в одном режиме. Очки угроз для этой карты замораживаются, чтобы рассказчик не отыгрался после возвращения. Мелкие события остаются.

## 5. Стазис

- У карты локальные часы: мировое время минус суммарное время в стазисе. Объекты карты во время её тика видят локальное время.
- Мир (дата, сезон, караваны, исследования, мировые квесты) идёт по общим часам.
- После разморозки сезон может скакнуть — показываем предупреждение.
- Квесты, привязанные к замороженной карте, ставятся на паузу.
- Выход пешки с карты в мир требует пересчёта её таймеров в мировое время. Самое хрупкое место.
- Стазис возможен только на карте без чужих пешек.

## 6. Сервер и сохранения

Сервер лёгкий: консольное приложение .NET 10, игру не симулирует.

- хранит канонический сейв, принимает снимки карт от владельцев;
- ведёт общие часы, упорядочивает команды;
- хранит права: владельцы карт, выданные разрешения;
- пересылает данные между игроками.

Сценарий: один игрок поднимает сервер локально → первый играет → второй заходит в активную сессию (снимок мира, догон команд, приём авторитета над своей картой) → выход любого сохраняет его карту на сервер.

Копия сейва с номером версии хранится у обоих игроков, поэтому поднять сервер может любой. Сервер при старте предупреждает, если у второго игрока версия новее. Тот же сервер можно держать на VPS.

## 7. Права на чужом поселении

Уровни: наблюдатель, только строительство, полный контроль. Владелец отзывает права одной кнопкой.

## 8. Идеи на потом

Курсоры и пинги второго игрока; кнопка «SOS»; общие чертежи с утверждением владельцем; аренда пешек; посылки дроп-подами.

## 10. Что сейчас сделано иначе, чем задумано выше (14.11.2026)

Раздел честно фиксирует расхождения плана и кода. Код этих пунктов **в игре не запускался**: проверен компилятором и установкой патчей на сборку игры (`docs/BUILD.md`).

1. **Все карты считают все игроки.** Пункты 2.1–2.3 описывают цель: чужую карту считает только её владелец. Сейчас проще: один общий ход времени, каждая команда на любой карте исполняется у всех. Владелец проекта решил (14.11.2026), что для больших сборок с двумя-тремя и более крупными поселениями это не годится; схема «поселение считает владелец» спроектирована в разделе 11 и делается по этапам. До конца её первого этапа тесты идут на схеме «все считают всё».
2. **Вход в идущую игру — снимок всей игры, а не мира.** Вошедший просит снимок командой в общем порядке; его снимает игрок, который держит сессию; загружают все, включая его самого (иначе загруженная и непрерывная игры идут по-разному). Отдача копии с сервера без хоста — не сделана.
3. **Расхождение лечится тем же снимком всей игры**, а не пересылкой одной карты (пункт 2.4). Нужен сигнал от сервера (код `Notice`, предложен агенту B).
4. **Перехват ввода — общий не везде** (пункт 2.5). Разметка, кнопки объектов, контекстные меню и выбор цели перехватываются общим механизмом без перечисления методов. Окна с собственным содержимым (приоритеты работ, расписание, политики, счета, фильтры, исследования) — по списку методов и полей игры: общего способа для них нет. Окна модов, которых нет в списке, меняют игру только у одного игрока; спасает сверка хешей и общий снимок. Подробно — `docs/INPUT.md`.
5. **Правила игры, которые пришлось изменить ради совпадения симуляции:**
   - вещи обновляются с постоянной частотой, как при максимальном приближении камеры (в одиночной игре частота зависит от камеры) — возможна потеря производительности на больших колониях, замера нет;
   - «пока игрок не смотрит» (механики Anomaly) означает «всегда»;
   - список «предпочитаемых имён» игрока на имена новых пешек не влияет;
   - язык игры у игроков может быть разным (требование совпадения снято 14.11.2026): тексты, которые игра собирает из правил языка, в тике считаются на отдельном состоянии `Rand`. У игроков с разными языками имена новых пешек, названия заданий и описания предметов искусства могут отличаться до ближайшей общей загрузки мира;
   - состояние, которое игра обновляет раз в кадр, а читает в тике (яркость неба, подключение построек к электросетям, комнаты, сетка освещения), обновляется перед каждым тиком.
6. **Права** (раздел 7): таблица, окно «Карты и права», заявка на карту и выдача уровней сделаны; проверка — на сервере и, заранее, на клиенте. Имён игроков в окне пока нет (сервер не присылает состав игроков).

## 11. Проект: поселение считает только владелец (14.11.2026)

Решение владельца проекта: схема «все считают всё» не годится для больших сборок с несколькими крупными поселениями. Ниже — проект. Он **не написан и не запускался**; каждый этап заканчивается тестом в игре.

### 11.1. Что получает игрок

- Его компьютер считает своё поселение, общий мир и те чужие карты, на которые он сейчас смотрит как гость. Чужие поселения, куда он не заходил, не считаются и не нагружают процессор.
- «Перейти на поселение друга» — это вход гостем: владелец отдаёт снимок одной карты, дальше гость и владелец считают её вместе (как сейчас считают всю игру).
- Ушёл с чужой карты — перестал её считать.

### 11.2. Три вида состояния

| Состояние | Кто считает | Как остаётся одинаковым |
|---|---|---|
| Карта (вещи, пешки, свой `Rand`, свои номера вещей — уже раздельные, T-007) | Владелец и гости, которые сейчас на карте | Общий порядок команд + хеш карты, сверяют только те, кто её считает |
| Общий мир (дата, фракции, исследования, караваны, мировые пешки, глобальный `Rand`) | Все игроки | Общий порядок команд + хеш мира, сверяют все |
| Переход через границу «карта ↔ мир» | Владелец карты сообщает, остальные применяют | **Событие карты**: сообщение в общем порядке команд, исполняется у всех на одном тике |

Главное правило: **тик карты не пишет в общий мир напрямую и тик мира не читает чужую карту напрямую.** Всё, что пересекает границу, идёт событием.

Примеры событий карты → мир: очки исследования (накопленные за интервал), изменение отношений с фракцией, пешка или караван покинули карту (с полными данными пешек), богатство и число колонистов для рассказчика. Мир → карта: событие рассказчика для этой карты, прибытие каравана или капсул.

### 11.3. Кирпичи, которых ещё нет

1. **Снимок одной карты**: снять у владельца, применить у гостя в работающую игру (заменить или добавить карту). Сейчас есть только снимок всей игры. Сложность — ссылки с карты на мир (фракции, идеологии, задания, мировые пешки): их надо сохранять номерами и находить при загрузке.
2. **Спящая карта**: карта, которую этот компьютер не считает. Механизм пропуска тика есть (флаг `frozen`, T-007); нужен второй признак «считает другой игрок», который не сохраняется как стазис.
3. **Перехват записи из тика карты в мир**: список мест, где игра из тика карты меняет общее состояние (исследования, отношения фракций, рассказчик, задания, мировые пешки). Список заранее неизвестен. Инструмент поиска: тестовый режим, который считает хеш мира до и после тика каждой карты и пишет, какой метод его изменил.
4. **Рассказчик и задания по картам**: события для карты выбирают те, кто её считает (состояние рассказчика игра и так хранит на каждой карте отдельно). Задания, привязанные к карте, тикают вместе с ней. Мировые события и задания без карты считает один назначенный сервером игрок и рассылает результат. Здесь нужно отдельное исследование кода заданий.
5. **Присутствие на картах в протоколе** (сервер, агент B): кто какую карту считает; хеши карты сравниваются только между ними; команды карты доставляются всем (спящим — чтобы просто пропустить), снимок карты — адресно гостю.
6. **Сохранение**: полный мир теперь не лежит ни у одного игрока целиком — у каждого свежие только его карты. Сейв = мир от назначенного игрока + снимок каждой карты от владельца. Собирает сервер (T-044, агент B).

### 11.4. Этапы

| Этап | Что делается | Тест «готово» |
|---|---|---|
| 0 (сейчас) | Все считают всё | TST-014 … TST-045 |
| 1 | Снимок одной карты; спящая чужая карта; хеш мира; инструмент поиска записей в мир; перехват исследований и событий рассказчика | Два игрока, два поселения, никто не в гостях: каждый считает одну карту, хеш мира совпадает 3 игровых дня, время кадра не зависит от размера чужого поселения |
| 2 | Вход гостем и выход; хеш карты между владельцем и гостем; лечение расхождения снимком одной карты | Гость заходит на чужую карту, отдаёт приказ по выданным правам, выходит; хеши совпадают |
| 3 | Переходы между картами разных владельцев: караваны, капсулы, торговля (вместе с T-035, T-036 агента B) | Караван от одного игрока приходит к другому, вещи не дублируются и не пропадают |
| 4 | Задания, передача карты при выходе владельца (T-032 агента B), стазис и автопилот (T-043, T-041) | Тесты этих задач |

На этапе 1 вход гостя останавливает игру у всех на время загрузки (как сейчас при входе в сессию, по замеру около 9 секунд для снимка всей игры). Вход без остановки требует «локальных часов карты» — того же механизма, что и стазис (раздел 5); он отнесён к этапу 4.

### 11.5. Риски, названные честно

- **Неизвестное число мест записи из карты в мир.** Пропущенное место = расхождение мира. Инструмент из пункта 11.3.3 находит такие места в тесте, но не доказывает, что их больше нет; моды добавят свои.
- **Задания.** Их части держат ссылки на вещи карт и тикают глобально. Возможно, на первых этапах задания, затрагивающие чужую карту, придётся отключить.
- **Снимок одной карты** может оказаться заметно сложнее снимка всей игры из-за ссылок на мир.
- **Проверить некем.** Карту, которую считает один владелец, никто не сверяет: ошибка в его симуляции не будет замечена, пока не войдёт гость.
- Срок не называю: этап 1 — это четыре новых механизма, каждый с проверкой в игре.

## 12. Отряды в одном поселении (запрос владельца проекта, 14.11.2026)

Несколько игроков играют на одной карте. Пешек делят на отряды; каждый игрок управляет только своими.

### 12.1. Правила

- **Отряд** — имя, список игроков-участников и список пешек. Отряды живут в сейве (компонент игры), поэтому одинаковы у всех и переживают перезагрузку.
- **Пешка состоит не больше чем в одном отряде.** Перевод пешки в отряд 2 сам убирает её из отряда 1.
- **Игрок управляет пешкой отряда, только если он участник этого отряда.** Игрок отряда 2 не может приказывать пешкам отряда 1: призыв, приказ идти или атаковать, правый щелчок, кнопки пешки, её приоритеты работ, расписание, политики, разрешённая область, лечение.
- Права на карту (раздел 7) действуют как раньше: отряд ограничивает приказы пешкам, а не стройку и разметку.
- Пешки, которые разметили на работу, сами выполняют её как обычно: отряд ограничивает приказы игрока, а не ИИ пешки.

### 12.2. Предварительные решения (владелец может изменить)

1. **Пешка без отряда** — общая: ей приказывает любой игрок с правом `Full` на карту, как сейчас.
2. **Кто создаёт отряды и переводит пешек** — владелец карты. Участник может вывести из своего отряда свою пешку, чтобы она стала общей.
3. **Игрок может состоять в нескольких отрядах**, в отряде может быть несколько игроков.
4. **Владелец карты не управляет чужим отрядом** напрямую, только переводит пешек между отрядами.

### 12.3. Как это сделано технически

- Всё на клиенте и детерминированно, протокол не меняется. Команда несёт в своих данных номера пешек, которых касается. При исполнении в тике каждый клиент одинаково проверяет: автор — участник отряда каждой из этих пешек. Если нет, команда пропускается у всех, и состояние не расходится.
- Сервер содержимое команд не читает. Изменённый клиент мог бы обойти проверку у себя, но остальные клиенты команду всё равно не исполнят. Для игры с друзьями этого достаточно.
- Интерфейс заранее не даёт выделить чужих пешек для приказов: они видны, их можно осмотреть, кнопки приказов неактивны с подсказкой «пешка отряда N».
- Сложное место — команды, где пешка не указана явно: кнопка на постройке, которая назначает пешку; меню правого щелчка по предмету с выбранными пешками; перетаскивание в окне каравана. Для каждой такой команды пешки надо извлечь из выделения автора. Список — часть задачи T-061.

### 12.4. Этапы

| Задача | Что | Тест |
|---|---|---|
| T-060 | Состояние отрядов в сейве, команды «создать / переименовать / удалить отряд», «участники», «перевести пешку»; окно «Отряды» | TST-060, ч. 1 |
| T-061 | Проверка прав на пешку при исполнении всех команд, неактивные приказы чужим пешкам в интерфейсе | TST-060, ч. 2 |

## 13. Выделенный сервер (запрос владельца проекта, 14.11.2026)
