# Сборка модов «fff» (Steam, коллекция 3836442447): разбор перед T-054

27.11.2026, агент A. Разбор по файлам модов на машине A (`steamapps/workshop/content/294100`), **без запуска игры**. Всё о поведении модов ниже — предположения по составу файлов и названиям, пока не проверено прогоном.

Прежняя версия без модов сохранена: ветка `stable/vanilla` и метка `vanilla-stable-1` (коммит `3a44ac6`).

## Состав

- Установлено 141 мод (столько же в коллекции). Включено в игре сейчас 8 — ядро, DLC, Harmony, RWMLWC.
- 133 заявляют версию 1.7. **Без 1.7:** Combat Extended, RimHUD, Eccentric Tech — Core и Foxy's Armory 2.0, Who shot my leg off?, Clean Textures, Adaptive Storage Framework, The Dead Man's Switch — More Synthetics. Combat Extended из них самый тяжёлый: он переделывает бой целиком. Если он не грузится на 1.7, из прогона его надо убрать.
- 66 модов — только XML (вещи, оружие, фракции, расы, постройки). Для синхронизации это самая безопасная часть: игра исполняет их стандартным кодом, который мод уже синхронизирует.
- 75 модов со своим кодом (DLL). От них зависят расхождения.
- **Конфликт:** в сборке есть RimWorld Multiplayer (`rwmt.Multiplayer`) и Multiplayer Compatibility (`rwmt.MultiplayerCompatibility`). Это другой сетевой мод. Вместе с RWMLWC их включать нельзя: оба перехватывают тик и ввод.
- Harmony: в моде Harmony для 1.7 стоит Harmony 3.0.0.0, мы собираемся с тем же. Dubs кладут в папку 1.7 ту же 3.0.0.0. Но Humanoid Alien Races кладёт в 1.7 версию 2.4.3, а Muzzle Flash — 2.3.3. Обычно грузится копия мода Harmony, и он идёт первым, но это проверяется на этапе 1: наш мод требует Harmony 3.
- Память: 63 ГБ, два клиента со сборкой на одной машине помещаются.

## Готовая совместимость, которую можно использовать

Multiplayer Compatibility (лицензия MIT) упоминает 25 модов с кодом из этой сборки. Среди них VEF, VPE, VFE Empire, VIE Memes, VTE, VSE, HAR, Fortified, RimDark, DMS и Expedition, Sparkling Worlds, Alpha Animals, Dubs Mint, Utility Columns и Nice Plants Menu.

YART и Fortified сами поставляют `0MultiplayerAPI.dll`: они объявляют свои действия через интерфейс Multiplayer API.

Отсюда главное решение по объёму: вместо того чтобы вписывать действия каждого мода в `MethodCommands`, можно **реализовать интерфейс Multiplayer API поверх нашей шины команд**. Тогда описания из Multiplayer Compatibility и из самих модов заработают в RWMLWC без переписывания.

Это крупная работа. Нужно реализовать:
- синхронизацию методов, полей и замыканий;
- сериализаторы своих типов;
- окна-диалоги.

Сначала нужно проверить, что наш `ValueCodec` и `MethodCommands` это покрывают. Это предположение: интерфейс API не разобран декомпиляцией.

## План T-054 по этапам

| Этап | Что | Оценка |
|---|---|---|
| 1. Загрузка | Сборка без rwmt и без модов не для 1.7, плюс RWMLWC. Игра грузится, в `Player.log` нет ошибок наших патчей, конфликты Harmony на наших методах выписаны | 1 сессия |
| 2. Тишина | Два клиента, новая колония, 3 игровых дня без ввода. Сервер чист? Если нет — поиск виновника делением сборки пополам (по 7–8 прогонов на виновника) и правка у нас или исключение мода | 1–4 сессии, зависит от числа виновников |
| 3. Действия | Сценарий с кнопками и окнами модов из групп выше. Список действий, которые не синхронизируются | 1–2 сессии |
| 4. Синхронизация действий | Либо мост Multiplayer API (переиспользует Multiplayer Compatibility), либо поимённые записи в `MethodCommands` для каждого мода | мост: 5–10 сессий; поимённо: по 0,5–1 сессии на мод |
| 5. Режимы | Общий снимок, вход второго игрока, раздельный счёт колоний с полной сборкой: размер снимка, время перезагрузки | 1–2 сессии |

Итого до «играется вдвоём без частых перезагрузок»: порядка 10–20 сессий агента. Точнее станет после этапов 1–2. Неизвестно главное: сколько модов ломают детерминизм без ввода. Каждый такой мод — отдельный поиск.
