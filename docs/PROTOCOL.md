# Протокол (v0, `ProtocolVersion = 1`)

Код: `Source/Shared/Protocol/`. Тесты: `Source/Tests/ProtocolRoundTripTests.cs` (TST-011).
Изменение любого сообщения повышает `ProtocolVersion` и идёт через запись КОНТРАКТ в `AGENT_LOG.md`.

## Кадр

```
int32  длина   — байты после этого поля (тип + тело), little-endian
uint16 тип     — MessageType
...    тело
```

- Все числа little-endian.
- Строка: `int32` длина в байтах + UTF-8. Блок данных: `int32` длина + байты.
- Лимиты (`ProtocolLimits`): кадр 4 МиБ, строка 64 КиБ, кусок снимка 256 КиБ, частей хеша 256.
- Любая ошибка формата (обрыв, лишние байты, неверная длина, неизвестный тип, не UTF-8) — `ProtocolException`. Получатель рвёт соединение.
- Потоковый транспорт: `ProtocolCodec.EncodeFrame` / `TryDecodeFrame` (собирает кадр из кусков). Транспорт с готовыми сообщениями: `EncodeBody` / `DecodeBody`.

## Сообщения

| № | Тип | Направление | Поля |
|---|---|---|---|
| 1 | `Hello` | клиент → сервер | `ProtocolVersion`, `ModId`, `GameVersion`, `PlayerName`, `ModListHash` (u64) |
| 2 | `Welcome` | сервер → клиент | `PlayerId`, `ServerTick`, `SessionSeed` (u32) |
| 3 | `Reject` | сервер → клиент | `Reason` (`RejectReason`), `Detail` |
| 4 | `Command` | клиент → сервер | `ClientSeq`, `MapId`, `Kind`, `Payload` |
| 5 | `CommandOrdered` | сервер → все | `Seq` (i64), `Tick`, `PlayerId`, `ClientSeq`, `MapId`, `Kind`, `Payload` |
| 6 | `Tick` | сервер → все | `TickUpTo`, `Speed` (0 — пауза, 1..4 — `TimeSpeed`) |
| 7 | `SpeedRequest` | клиент → сервер | `Speed` |
| 8 | `SnapshotChunk` | в обе стороны | `SnapshotId`, `MapId`, `Tick`, `ChunkIndex`, `ChunkCount`, `Data` |
| 9 | `MapHash` | клиент → сервер | `MapId`, `Tick`, `Total` (u64), `Parts` — список (имя, u64) |

`MapId` — `Map.uniqueID`; `-1` (`ProtocolIds.WorldMapId`) — уровень мира.

## Сценарий

1. Клиент подключается и шлёт `Hello`. Сервер отвечает `Welcome` или `Reject` и закрывает соединение.
2. Игрок что-то делает → клиент шлёт `Command` и **не исполняет его сам**.
3. Сервер назначает команде `Seq` и тик `T` = текущий `TickUpTo`, рассылает `CommandOrdered` всем, включая автора. **Команду исполняют после завершения тика `T` и до начала тика `T+1`** (уточнение T-013: так команды принимаются и на паузе, и ни один клиент не успевает пройти мимо — дальше `T` ему тикать ещё не разрешено).
4. Сервер рассылает `Tick`. Гарантия: команда с тиком `T` приходит раньше любого `Tick` с `TickUpTo > T`. Клиент тикает до `TickUpTo`; после каждого тика исполняет команды с этим `T` по возрастанию `Seq`.
5. Клиент периодически шлёт `MapHash`; сервер сравнивает хеши игроков по `(MapId, Tick)` и при расхождении запускает пересылку карты (T-034) кусками `SnapshotChunk`.

Что решено **не в v0** и остаётся задачам: формат `Payload` команд и реестр `Kind` (A, T-020–T-023), формат и сжатие данных снимка (A, T-030), права (B, T-031), чат и пинг (B, T-025).

## Транспорт (T-012)

Код: `Source/Net/` (сборка `RWMLWC.Net.dll`, используется клиентом и сервером). Тесты: `Source/Tests/TransportTests.cs` (TST-012).

- `IConnection` — соединение с очередью входящих (`TryReceive` для главного потока игры, `ReceiveAsync` для сервера). `Send` потокобезопасен.
- **QUIC** (`QuicTransport`, `QuicServer`): ALPN `rwmlwc/1`. Два потока, оба открывает клиент: управление (все сообщения, кроме `SnapshotChunk`) и объёмный (`SnapshotChunk`) — снимок не задерживает команды. Порядок сохраняется внутри потока.
- Сертификат сервера самоподписанный, хранится в `<data>/server.pfx` (отпечаток не меняется между запусками). Клиент проверяет отпечаток SHA-256 — игрок передаёт его другу вместе с адресом и портом.
- Таймаут бездействия 10 с, keep-alive 2 с: обрыв (в т. ч. убитый процесс сервера) обнаруживается не позже чем через ~10 с.
- `ReconnectingClient` — переподключение с паузой 0,5 → 5 с. Состояние сессии транспорт не восстанавливает: после переподключения верхний слой заново шлёт `Hello` (докачка команд — T-013).
- `InMemoryConnection.CreatePair()` — пара соединений в памяти для тестов, сообщения проходят через кодек.
- Сервер для проверки: `dotnet RWMLWC.Server.dll --echo [--port N] [--data папка]` печатает `LISTENING <порт> <отпечаток>` и возвращает каждое сообщение отправителю.

## Сервер (T-013)

Код: `Source/Server/Session.cs` (логика, однопоточная, без таймеров), `SessionHost.cs` (QUIC + цикл каждые 10 мс). Тесты: `Source/Tests/SessionTests.cs` (TST-013). Запуск: `dotnet RWMLWC.Server.dll [--port N] [--data папка] [--start-tick T] [--seed S]`.

- **Рукопожатие.** Первое сообщение — `Hello`, иначе разрыв; нет `Hello` за 10 с — разрыв. Отказ (`Reject`, затем закрытие): другая версия протокола, чужой `ModId`, пустое имя, версия игры или `ModListHash` не как у первого вошедшего, имя уже в сети, сервер полон (8). Иначе `Welcome` (`PlayerId` с 1, `ServerTick` = текущий `TickUpTo`, `SessionSeed`) и сразу `Tick` с текущим разрешением.
- **Возврат.** Игрок с тем же именем после обрыва получает прежний `PlayerId`. Догона пропущенного нет (T-045).
- **Часы.** 60 тиков/с × базовый множитель скорости игры: 1→1, 2→3, 3→6, 4→15. `Tick` рассылается, когда меняется `TickUpTo` или скорость.
- **Скорость.** Минимум из `SpeedRequest` игроков в сети; пауза любого — пауза всех; ушедший не учитывается. **Новый и вернувшийся игрок держат паузу**, пока не пришлют `SpeedRequest` (например, после загрузки).
- **Команды.** Общий `Seq` без пропусков; игроки обрабатываются по возрастанию номера, команды каждого — в порядке прихода. Принимаются и на паузе.
- **Хеши.** `MapHash` сравниваются по `(MapId, Tick)`, при несовпадении `Total` — запись в лог и событие `Session.Desync` (реакция — T-034).
- **Снимки.** `SnapshotChunk` пересылается всем остальным игрокам в сети.
