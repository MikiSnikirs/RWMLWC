# Протокол (`ProtocolVersion = 2`)

Код: `Source/Shared/Protocol/`. Тесты: `Source/Tests/ProtocolRoundTripTests.cs` (TST-011).
Изменение любого сообщения повышает `ProtocolVersion` и идёт через запись КОНТРАКТ в `AGENT_LOG.md`.

## Кадр

```
int32  длина   — байты после этого поля (тип + тело), little-endian
uint16 тип     — MessageType
...    тело
```

- Все числа little-endian.
- Строка: `int32` длина в байтах + UTF-8. Блок данных: `int32` длина + байты.
- Лимиты (`ProtocolLimits`): кадр 4 МиБ, строка 64 КиБ, кусок снимка 256 КиБ, частей хеша 256.
- Любая ошибка формата (обрыв, лишние байты, неверная длина, неизвестный тип, не UTF-8) — `ProtocolException`. Получатель рвёт соединение.
- Потоковый транспорт: `ProtocolCodec.EncodeFrame` / `TryDecodeFrame` (собирает кадр из кусков). Транспорт с готовыми сообщениями: `EncodeBody` / `DecodeBody`.

## Сообщения

| № | Тип | Направление | Поля |
|---|---|---|---|
| 1 | `Hello` | клиент → сервер | `ProtocolVersion`, `ModId`, `GameVersion`, `PlayerName`, `ModListHash` (u64), `SaveWorldId` (u64), `SaveTick` (v2) |
| 2 | `Welcome` | сервер → клиент | `PlayerId`, `ServerTick`, `SessionSeed` (u32), `SaveWorldId` (u64), `SaveTick` (v2) |
| 3 | `Reject` | сервер → клиент | `Reason` (`RejectReason`), `Detail` |
| 4 | `Command` | клиент → сервер | `ClientSeq`, `MapId`, `Kind`, `Required` (`PermissionLevel`, с v2), `Payload` |
| 5 | `CommandOrdered` | сервер → все | `Seq` (i64), `Tick`, `PlayerId`, `ClientSeq`, `MapId`, `Kind`, `Payload` |
| 6 | `Tick` | сервер → все | `TickUpTo`, `Speed` (0 — пауза, 1..4 — `TimeSpeed`) |
| 7 | `SpeedRequest` | клиент → сервер | `Speed` |
| 8 | `SnapshotChunk` | в обе стороны | `SnapshotId`, `MapId`, `Tick`, `ChunkIndex`, `ChunkCount`, `Data` |
| 9 | `MapHash` | клиент → сервер | `MapId`, `Tick`, `Total` (u64), `Parts` — список (имя, u64) |
| 10 | `MapClaim` | клиент → сервер | `MapId` — «карта моя» (v2) |
| 11 | `GrantPermission` | клиент → сервер | `MapId`, `PlayerId`, `Level`; `None` — отзыв (v2) |
| 12 | `Permissions` | сервер → все | список карт: `MapId`, `OwnerPlayerId`, выданные права (`PlayerId`, `Level`) (v2) |
| 13 | `CommandRejected` | сервер → автору | `ClientSeq`, `MapId`, `Required`, `Had` (v2) |
| 14 | `Notice` | сервер → клиенту | `Code` (`NoticeCode`), `Text` — предупреждение без разрыва (v2) |
| 15 | `SnapshotApplied` | клиент → сервер | `SnapshotId`, `Tick` — снимок загружен (v2) |
| 16 | `Players` | сервер → все | состав сессии: список (`PlayerId`, `Name`, `Online`, `PingMs`) по возрастанию номера (v3) |
| 17 | `Ping` | в обе стороны | `Timestamp` (u64, часы отправителя) — отвечает сам транспорт (v3) |
| 18 | `Pong` | в обе стороны | `Timestamp` из `Ping` (v3) |
| 19 | `Chat` | клиент → сервер → все | `PlayerId` (от клиента не читается), `Text` (v3) |

`NoticeCode`: `Info` 0, `NewerSaveOnClient` 1, `DifferentWorld` 2, `Desync` 3 (v3).

`MapId` — `Map.uniqueID`; `-1` (`ProtocolIds.WorldMapId`) — уровень мира.

## Сценарий

1. Клиент подключается и шлёт `Hello`. Сервер отвечает `Welcome` или `Reject` и закрывает соединение.
2. Игрок что-то делает → клиент шлёт `Command` и **не исполняет его сам**.
3. Сервер назначает команде `Seq` и тик `T` = текущий `TickUpTo`, рассылает `CommandOrdered` всем, включая автора. **Команду исполняют после завершения тика `T` и до начала тика `T+1`** (уточнение T-013: так команды принимаются и на паузе, и ни один клиент не успевает пройти мимо — дальше `T` ему тикать ещё не разрешено).
4. Сервер рассылает `Tick`. Гарантия: команда с тиком `T` приходит раньше любого `Tick` с `TickUpTo > T`. Клиент тикает до `TickUpTo`; после каждого тика исполняет команды с этим `T` по возрастанию `Seq`.
5. Клиент периодически шлёт `MapHash`; сервер сравнивает хеши игроков по `(MapId, Tick)` и при расхождении запускает пересылку карты (T-034) кусками `SnapshotChunk`.

Что решено **не в v0** и остаётся задачам: формат `Payload` команд и реестр `Kind` (A, T-020–T-023), формат и сжатие данных снимка (A, T-030), права (B, T-031), чат и пинг (B, T-025).

## Транспорт (T-012)

Код: `Source/Net/` (сборка `RWMLWC.Net.dll`, используется клиентом и сервером). Тесты: `Source/Tests/TransportTests.cs` (TST-012).

- `IConnection` — соединение с очередью входящих (`TryReceive` для главного потока игры, `ReceiveAsync` для сервера). `Send` потокобезопасен.
- **QUIC** (`QuicTransport`, `QuicServer`): ALPN `rwmlwc/1`. Два потока, оба открывает клиент: управление (все сообщения, кроме `SnapshotChunk`) и объёмный (`SnapshotChunk`) — снимок не задерживает команды. Порядок сохраняется внутри потока.
- Сертификат сервера самоподписанный, хранится в `<data>/server.pfx` (отпечаток не меняется между запусками). Клиент проверяет отпечаток SHA-256 — игрок передаёт его другу вместе с адресом и портом.
- Таймаут бездействия 10 с, keep-alive 2 с: обрыв (в т. ч. убитый процесс сервера) обнаруживается не позже чем через ~10 с.
- `ReconnectingClient` — переподключение с паузой 0,5 → 5 с. Состояние сессии транспорт не восстанавливает: после переподключения верхний слой заново шлёт `Hello` (докачка команд — T-013).
- `InMemoryConnection.CreatePair()` — пара соединений в памяти для тестов, сообщения проходят через кодек.
- Сервер для проверки: `dotnet RWMLWC.Server.dll --echo [--port N] [--data папка]` печатает `LISTENING <порт> <отпечаток>` и возвращает каждое сообщение отправителю.

## Сервер (T-013)

Код: `Source/Server/Session.cs` (логика, однопоточная, без таймеров), `SessionHost.cs` (QUIC + цикл каждые 10 мс). Тесты: `Source/Tests/SessionTests.cs` (TST-013). Запуск: `dotnet RWMLWC.Server.dll [--port N] [--data папка] [--start-tick T] [--seed S]`.

- **Рукопожатие.** Первое сообщение — `Hello`, иначе разрыв; нет `Hello` за 10 с — разрыв. Отказ (`Reject`, затем закрытие): другая версия протокола, чужой `ModId`, пустое имя, версия игры или `ModListHash` не как у первого вошедшего, имя уже в сети, сервер полон (8). Иначе `Welcome` (`PlayerId` с 1, `ServerTick` = текущий `TickUpTo`, `SessionSeed`), `Permissions`, `Players` (v3) и `Tick` с текущим разрешением.
- **Возврат.** Игрок с тем же именем после обрыва получает прежний `PlayerId`. Догона пропущенного нет (T-045).
- **Часы.** 60 тиков/с × базовый множитель скорости игры: 1→1, 2→3, 3→6, 4→15. `Tick` рассылается, когда меняется `TickUpTo` или скорость.
- **Скорость.** Минимум из `SpeedRequest` игроков в сети; пауза любого — пауза всех; ушедший не учитывается. **Новый и вернувшийся игрок держат паузу**, пока не пришлют `SpeedRequest` (например, после загрузки).
- **Команды.** Общий `Seq` без пропусков; игроки обрабатываются по возрастанию номера, команды каждого — в порядке прихода. Принимаются и на паузе.
- **Хеши.** `MapHash` сравниваются по `(MapId, Tick)`, при несовпадении `Total` — запись в лог, событие `Session.Desync` и (v3) `Notice Desync` всем в сети с текстом «карта M тик T: игрок X ≠ игрок Y» — не чаще раза в 600 тиков (`ProtocolLimits.DesyncNoticeIntervalTicks`) на карту. Что делать — решает клиент (T-034).
- **Пинг (v3).** `Ping`/`Pong` обрабатывает `ConnectionBase` в потоке приёма: на `Ping` сразу уходит `Pong`, по `Pong` обновляется `IConnection.RoundTripMs`; приложению они не передаются. Сервер шлёт `Ping` каждому игроку раз в секунду. Через Steam-мост к консольному серверу (`ConnectionRelay`) каждое звено отвечает само, поэтому сервер видит пинг только до моста. В сессии в игре хоста Steam-соединение идёт в сессию напрямую, и пинг измеряется от начала до конца.
- **Чат (v3).** Сервер обрезает пробелы, пустое отбрасывает, текст длиннее 500 символов обрезает, от одного игрока принимает не больше 5 сообщений за 5 с (лишние отбрасывает и пишет в лог). Рассылает всем в сети, включая автора, с номером автора.
- **Состав (v3).** `Players` — все когда-либо входившие игроки, ушедший остаётся с `Online = false`. Новый или вернувшийся игрок получает его после `Welcome` и `Permissions`; остальным он рассылается, когда кто-то входит, возвращается или уходит (уход сервер замечает в ближайшем `Pump`), и раз в 2 с, если изменился чей-то пинг.
- **Снимки.** `SnapshotChunk` пересылается всем остальным игрокам в сети.

## Права на карты (T-031, v2)

Уровни `PermissionLevel`: `None` (0) — нет доступа, `Observer` (1) — видит, команд не отдаёт, `Build` (2) — разметка и чертежи, `Full` (3) — всё.

- Карта получает владельца по `MapClaim`: свободная — заявителю, занятая — заявка отклоняется (в ответ — текущая таблица). Мир (`MapId = -1`) владельца не имеет.
- Уровень игрока на карте: мир и карта без владельца — `Full` для всех; владелец — `Full`; остальные — выданный владельцем уровень или `None`.
- `GrantPermission` принимается только от владельца; `Level = None` — отзыв.
- Команда принимается, если уровень автора на её карте ≥ `Command.Required`. Иначе автору — `CommandRejected`, остальным ничего не уходит, `Seq` не расходуется.
- Отзыв действует с первой команды, обработанной после него. Порядок внутри одного прохода сервера — по номеру игрока, поэтому отзыв владельца и команда гостя в одном проходе: сначала отзыв, если номер владельца меньше.
- `Permissions` (вся таблица) уходит новому игроку сразу после `Welcome` и всем — при каждом изменении. Права хранятся по номеру игрока и переживают его переподключение.
- **Не сделано:** снятие владения и передача авторитета (T-032); что видит гость с `Observer`/`None` (пересылка снимков по правам) — T-033.

## Хранение сейва на сервере (T-044, v2)

Код: `Source/Server/SaveStore.cs`, сборка снимка — `Session.CollectWorldSnapshot`. Тесты: `Source/Tests/SaveStoreTests.cs` (TST-044).

- **Версия копии = игровой тик**, на котором она снята, плюс идентификатор мира (`SaveWorldId`; клиенту — `Find.World.info.persistentRandomValue`). Тик в мире только растёт, поэтому у одного мира бо́льший тик = новее.
- Сервер собирает из `SnapshotChunk` снимок **мира** (`MapId = -1`, куски в любом порядке) и сохраняет в `<data>/saves/world-<мир>-tick-<тик>.snapshot` + `.meta` (тик, время, размер, SHA-256). Запись через временный файл. Хранятся последние 5 копий. Мир берётся из `Hello.SaveWorldId` отправителя; снимок другого мира, неполный или с несогласованными кусками не сохраняется. Пересылка кусков остальным игрокам — как раньше.
- При запуске сервер берёт последнюю копию: её тик становится стартовым (если не задан `--start-tick`), мир и тик уходят игрокам в `Welcome`.
- **Защита от старой копии:** игрок с копией того же мира и бо́льшим тиком → `Notice NewerSaveOnClient` всем и «ВНИМАНИЕ» в консоли сервера. Копия другого мира → `Notice DifferentWorld` этому игроку. Соединение не рвётся — решают люди.
- **Не сделано:** отдача копии сервера входящему игроку (T-045), что делать по предупреждению (интерфейс — клиент).

## Выделенный сервер (T-058)

`SessionOptions.Dedicated` (консольный сервер). В пустой сессии часы до `Welcome` встают на тик мира следующего игрока: его сейв, если он того же мира и новее копии сервера (или если копии нет), иначе копия сервера. Если мира нет ни там, ни там, игрок получает `Reject`. Игроку, который один в сети и просит мир (команда вида 100, `RequestWorldSnapshotKind` клиента), сервер шлёт куски своей копии: `SnapshotId = Seq & 0x7FFFFFFF` его просьбы, `MapId = -1`, тик копии. Байты протокола не меняются. Чат сервера — `Chat` с `PlayerId = 0`. Подробности и команды консоли — `docs/DEDICATED_SERVER.md`.

## Отдающий мир и автосохранение (v4, T-062)

- Команда вида **100** (`ProtocolIds.RequestWorldSnapshotKind`, «общий снимок мира»). Клиент шлёт её с пустым `Payload`. Сервер рассылает `CommandOrdered` с `Payload` = int32 номер отдающего (`WorldSnapshotOrder`). Отдающий — игрок в сети с загруженным миром (вошёл со своим сейвом на тике сервера или подтвердил `SnapshotApplied`) с **наименьшим пингом до сервера**; просивший без мира не выбирается. `0` — мир отдаёт сам сервер (выделенный, своя копия).
- Команда вида **101** (`SaveWorldSnapshotKind`, только от сервера, `PlayerId = 0`) — автосохранение. Отдающий из `Payload` шлёт куски мира с `SnapshotId = Seq & 0x7FFFFFFF`. Остальные ничего не делают. Сервер **не пересылает** эти куски игрокам, а сохраняет копию. Когда: раз в `SessionOptions.AutosaveInterval` и когда игрок с миром вышел, если тик изменился. Клиентскую 101 сервер отбрасывает.
- **Расхождение**: кроме `Notice Desync`, сервер сам ставит в порядок команду 100 (`PlayerId = 0`) с отдающим. Клиент на `Notice` больше не просит снимок.

## Сессия в игре хоста (T-019)

Код: `Source/ServerCore/` (сессия как библиотека `RWMLWC.ServerCore.dll`: `Session`, `SessionHost`, `SaveStore`; её же запускает консольный сервер), `Source/Client/Net/HostedSession.cs`.

- `HostedSession.Start(startTick, port, steam, seed)` — сессия в фоновом потоке игры. QUIC слушает только `127.0.0.1` (через него подключается сама игра хоста), друзья приходят через Steam: входящее Steam-соединение отдаётся сессии напрямую (`SessionHost.Enqueue`), без промежуточного QUIC. Данные — `<данные игры>/RWMLWC/server/` (сертификат, копии мира, `session-log.txt`).
- Режим разработчика → отладочные действия → RWMLWC: «Host session here (Steam)» (сессия с текущего тика + подключение своей игры + сообщение со SteamID для друга), «Stop hosted session».
- Автотест: `net-test.txt` с `role=hostsession`, `port`, `starttick`, `seed`, `steam`; скрипт `tools/run-tst019.sh` — два экземпляра игры со своими папками данных (список модов меняется только в копии настроек).
- **Нет пока:** подключения друга через Steam из клиента A (нужна перегрузка `LockstepClient.Connect` с готовым соединением), интерфейса вне режима разработчика.
