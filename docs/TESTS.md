## TST-005: порядок проверки

Часть А (вручную, без хеша состояния). Режим разработчика, меню отладочных действий, раздел RWMLWC:

1. «Per-map sim: on/off» — включить. Минуту играть на скорости 3: колония работает как обычно, красных ошибок нет.
2. «Freeze/unfreeze current map» — пешки и предметы на карте замирают, игровые часы идут дальше, ошибок нет.
3. Повторить действие — карта оживает, пешки продолжают дела.
4. «Log per-map sim state» — скопировать строки `[RWMLWC]` из лога в журнал прогонов.
5. Сохранить игру, загрузить — ошибок нет.
6. «Per-map sim: on/off» — выключить, игра продолжается без ошибок.

Часть Б (после T-010, хеш состояния): две карты, одна заморожена; хеш замороженной не меняется, хеш тикающей совпадает с прогоном, где второй карты нет вовсе.

## TST-017: совместная сессия на двух компьютерах

Две части, одна встреча. Часть 1 сети не требует, часть 2 — тест транспорта агента B (TST-012 между машинами, затем TST-016).

**Что должно совпадать на обеих машинах:** RimWorld той же версии (сейчас 1.7.5005 rev1082), все пять DLC, включены только Harmony и RWMLWC, мод собран из одного и того же коммита `main`, один и тот же файл сейва.

**Часть 1 — детерминизм (агент A ведёт, обе машины исполняют):**

1. Владелец машины A передаёт владельцу машины B файл сейва `Поселение5.rws` лично (не через репозиторий) — в папку `Saves` игры.
2. На каждой машине в папке данных игры, `RWMLWC/arm-determinism-run.txt`:
   ```
   armed=1
   save=Поселение5
   scenarios=none,raid,twomaps
   perprocess=1
   ticks=10000
   trace=1
   quit=1
   ```
   и `RWMLWC/automation-progress.txt` с содержимым `0`.
3. Запустить игру один раз и не трогать, пока она не закроется окончательно (три прогона, игра сама перезапускается между ними).
4. Файлы `hash-*.txt` трёх прогонов положить в репозиторий: `docs/test-runs/data/TST-017/A/` и `.../B/`, по своей ветке. Файлы `randtrace-*.txt` и `things-*.txt` в репозиторий не класть (большие); оставить на машине до конца разбора.
5. Агент A сравнивает пары файлов по сценариям. Ожидание заранее неизвестно: сценарий `twomaps` почти наверняка разойдётся на второй карте (генерация карты различается даже между запусками на одной машине), это не провал. Важны первая карта во всех трёх сценариях и рейд.

**Часть 2 — транспорт через Steam, TST-016 (агент B ведёт).** Проброс портов не нужен; QUIC между машинами напрямую (TST-012) отдельно не гоняем — он проверен на одной машине и внутри моста.

Нужно: на обеих машинах запущен Steam, игра собрана из того же коммита, включены только Harmony и RWMLWC. Сервер отдельно запускать не нужно: в роли `host` игра сама поднимает сервер-эхо и Steam-мост.

1. **Машина A (хост).** Файл `RWMLWC/net-test.txt` в папке данных игры:
   ```
   armed=1
   role=host
   ```
   Запустить игру. В `RWMLWC/net-test-log.txt` появится строка `HOST READY ... host=<SteamID64>` — это число передать агенту B (через `log/A.md` или в чат людям). Игру не закрывать.
2. **Машина B (друг)** — делает агент B сам: `net-test.txt` с `armed=1`, `role=join`, `host=<SteamID64 хоста>`, запуск игры.
3. Друг сам прогоняет: подключение, первое эхо, 50 эхо (задержка), 200 команд по порядку, 4 куска снимка по 256 КиБ (скорость), закрытие и переподключение. Итог — строка `PASS join` или `FAIL ...` в его `net-test-log.txt`.
4. Когда у друга появится `WAITING FOR HOST CLOSE`, хост закрывает игру. Друг пишет, через сколько заметил обрыв.
5. Оба удаляют `net-test.txt` (иначе тест стартует при каждом запуске игры). Хост кладёт свой `net-test-log.txt` в `docs/test-runs/data/TST-016/A/`, друг — в `.../B/`.

Тест пройден: `PASS join` у друга, обрыв замечен. Записать задержку и скорость — по ним уточняется нижний предел скорости Steam (`SteamNet.SendRateMinBytes`).

Самопроверка на одной машине (без второго человека): `role=selftest` — три замера (только QUIC, только Steam, полный путь через мост) и `PASS selftest`.

## TST-014: клиент под управлением сервера

Нужен запущенный сервер сессии (`Source/Server`) и игра со сборкой, где есть `LockstepClient`.

1. Сервер: `dotnet RWMLWC.Server.dll --port 0 --start-tick 14998 --seed 7`. Он печатает строку `LISTENING <порт> <отпечаток>`. `--start-tick` — тик тестового сейва.
2. Файл-метка `RWMLWC/arm-determinism-run.txt`:
   ```
   armed=1
   save=Поселение5
   scenarios=none
   ticks=3000
   trace=0
   quit=1
   server=127.0.0.1:<порт>
   thumbprint=<отпечаток>
   name=auto
   ```
   и `automation-progress.txt` = `0`.
3. **Один клиент.** Запустить игру. Ожидание: в `automation-log.txt` строки `lockstep: connected`, `lockstep: Welcome`, затем обычный прогон до конца; игра закрывается. В логе сервера — вход игрока, хеши без расхождений.
4. **Два клиента.** В файл-метку добавить `holdsec=40` (иначе первый клиент начнёт тикать раньше, чем войдёт второй). Перезапустить сервер, записать `0` в `automation-progress.txt`, запустить два экземпляра игры (напрямую `RimWorld.exe`, не через Steam). Ожидание: оба прогона доходят до конца; файлы `hash-p<номер процесса>-*.txt` двух клиентов совпадают (`tools/compare_runs.py`); сервер не сообщает о расхождении хешей.
5. **Скорость.** Во время прогона двух клиентов скорость у обоих одинакова (в автоматическом прогоне оба просят третью скорость; если один экземпляр поставить на паузу вручную — встают оба).

Пункт 4 — это уже и первая версия T-015.

Одной командой (сборка, сервер, игра, сбор результатов в `RWMLWC/tst014/` в данных игры): `powershell -ExecutionPolicy Bypass -File tools\run-tst014.ps1` — один клиент; с `-Clients 2` — два экземпляра игры, у каждого своя папка данных (`-savedatafolder`).

## TST-015: двое суток игры без расхождения (часть 1 — обычная игра)

Два клиента, ваниль со всеми DLC, сервер, без сценария, 60 000 тиков (игровые сутки), камера c2 гуляет.

Запуск: `powershell -ExecutionPolicy Bypass -File tools/run-tst014.ps1 -Clients 2 -Ticks 60000 -Name tst015` (на машине A около 3 минут).

Ожидание: файлы хешей c1 и c2 совпадают на всех замерах; сервер не сообщает о расхождении; блока `RUN PROBLEMS` нет.

Часть 2 (по критерию T-015) — отдельные сценарии:
- смена яркости карты (Anomaly): сценарий `darkness` — на первом тике прогона на карте включается «неестественная тьма» на 30 000 тиков. Без сервера, два отдельных запуска игры: `powershell -ExecutionPolicy Bypass -File tools/run-offline.ps1 -Queue darkness,darkness -Ticks 10000 -Name tst015-dark -Camera`. Ожидание: в журнале дважды `scenario darkness: registered UnnaturalDarkness`, файлы хешей двух запусков совпадают;
- посадка гравикорабля (Odyssey): сценария нет — в тестовом сейве нет гравикорабля.

## TST-050: курсоры других игроков

Два клиента, сценарий `cursors`: c1 ставит свой курсор в точку рядом с центром карты, потом в другую; c2 останавливает гуляющую камеру, наводит её на курсор c1, пишет в журнал, что видит, и делает снимок игрой (`Screenshots` в данных c2).

3. Хеши c1 и c2 совпадают; сервер не сообщает о расхождении — курсоры на симуляцию не влияют.

## TST-072: отсутствующий владелец — без крупных угроз

Часть 1, без сервера: `powershell -ExecutionPolicy Bypass -File tools/run-offline.ps1 -Queue absence-raid -Ticks 1500 -Name tst072-raid`. ## TST-020: разметка одного игрока исполняется у обоих

Сценарий `designate`: на 300-м тике прогона клиент с `issuer=1` делает то же, что делает интерфейс, —
вызывает инструменты разметки: вырубка растений (квадрат 31×31 в центре карты), стена из дерева
(10 клеток линией и одна отдельная), склад 7×7, охота на первое подходящее животное. В сессии эти вызовы
перехватываются, уходят серверу командами и исполняются у обоих клиентов.

Запуск: `powershell -ExecutionPolicy Bypass -File tools\run-tst014.ps1 -Clients 2 -Scenario designate -Name tst020`.
Результаты — `RWMLWC/tst020/` в данных игры (`c1`, `c2`, `server-out.txt`).

Ожидание:
1. В `automation-log.txt` клиента c1 — строка `designate: … captured=5, sent=5`; строк `FAILED` и `LATE` нет ни у кого.
2. Строки `summary:` у c1 и c2 одинаковы; `executed=5 failed=0`; чертежей (`blueprints`) больше нуля, зон на одну больше, чем в прогоне без сценария, обозначений (`designations`) больше.
3. Файлы хешей c1 и c2 совпадают полностью; сервер не сообщает о расхождении.
4. В логе игры — строка `[RWMLWC] разметка: перехвачено методов N, не удалось 0`.

## TST-021: кнопки объектов, приказ атаки, меню

Сценарий `gizmo`, клиент с `issuer=1` действует как игрок (тики от начала прогона):
- 300 — нажимает «Призвать» у первого колониста;
- 400 — нажимает «Запретить» у первого подходящего предмета;
- 500 — приказывает этому колонисту атаковать ближайшее дикое животное (тот же вызов, что делает прицел после щелчка);
- 600 — нажимает «Выбрать растение» у первой зоны выращивания (если она есть в сейве) — у автора открывается меню;
- 700 — выбирает первую строку этого меню.

Запуск: `powershell -ExecutionPolicy Bypass -File tools\run-tst014.ps1 -Clients 2 -Scenario gizmo -Name tst021`.

Ожидание:
1. В `automation-log.txt` клиента c1 — строки `gizmo: …: sent=True` (атака — `sent=1`); строк `FAILED`, `LATE`, `dropped` нет ни у кого.
2. Строки `summary:` у c1 и c2 одинаковы: `drafted=1`, число запрещённых предметов изменилось на 1 против прогона без сценария, `executed` равно числу отправленных команд, `failed=0`.
3. Файлы хешей c1 и c2 совпадают полностью; сервер не сообщает о расхождении.
4. В логе игры — строки `[RWMLWC] кнопки: перехвачено методов N, не удалось 0` и `[RWMLWC] цели: перехвачено методов N, не удалось 0`.

**Автопрогон не проверяет перехват настоящего щелчка мышью** (сценарий отправляет команду сам). Это проверяется вручную, двумя игроками: один нажимает «Призвать», выбирает цель атаки, меняет растение в зоне — второй видит то же самое.

## TST-022: правый щелчок по карте

Сценарий `rightclick`, клиент с `issuer=1` (тики от начала прогона):
- 300 — призывает первого колониста; 400 — правый щелчок по свободной клетке рядом (приказ идти, исполняется сразу);
- 600 — отменяет призыв; 700 — правый щелчок по ближайшему предмету (у автора открывается меню приказов, если для пешки есть приказы); 800 — выбирает первую доступную строку меню.

Запуск: `powershell -ExecutionPolicy Bypass -File tools\run-tst014.ps1 -Clients 2 -Scenario rightclick -Name tst022`.

Ожидание:
1. В `automation-log.txt` c1 — строки `rightclick: move … sent`, `rightclick: item … sent`; строк `FAILED`, `LATE` нет ни у кого. `gizmo: first menu option: sent=False` допустимо, если для пешки не нашлось приказов (тогда меню не было).
2. Строки `summary:` у c1 и c2 одинаковы, включая `jobs=[…]` (занятие и клетка каждого колониста); `failed=0`.
3. Файлы хешей c1 и c2 совпадают полностью; сервер не сообщает о расхождении.

## Автоматические прогоны (T-008)

Файл `RWMLWC/arm-determinism-run.txt` в папке данных игры, строки `ключ=значение`:

| Ключ | Значение |
|---|---|
| `armed` | `0` — выключено |
| `save` | имя сейва без расширения: игра загрузит его сама сразу после запуска |
| `scenario` | `none`, `raid` (рейд на первую карту), `twomaps` (второе поселение), `twomaps-freeze` (второе поселение, заморожено) |
| `scenarios` | очередь через запятую: прогоны идут подряд за один запуск игры, сейв перезагружается между ними; счётчик пройденных — `automation-progress.txt`; пройденная очередь выключает метку сама |
| `perprocess` | `1` — между прогонами очереди игра перезапускается (штатный перезапуск игры), а не перезагружает сейв |
| `densefrom`, `denseto` | окно в тиках от старта, где хеш пишется каждый тик и идёт трассировка `Rand`; по умолчанию 0–300 |
| `snapat` | тик от старта, на котором сценарии `snap-save` и `snap-reload` снимают снимок; по умолчанию 2000 |
| `camera` | `1` — камера этого клиента во время прогона раз в 150 тиков прыгает в случайное место карты и меняет приближение. Скрипт `run-tst014.ps1` включает это у второго клиента: иначе камеры двух экземпляров одинаковы, и зависимость симуляции от камеры тест не поймает |
| `issuer` | `1` — этот клиент отдаёт приказы в сценарии `designate` |
| `traceframes` | глубина цепочки вызовов в трассировке, по умолчанию 7 |
| `holdsec` | в сессии: столько секунд после входа клиент не просит снять паузу (чтобы успел войти второй клиент) |
| `server`, `thumbprint`, `name` | адрес:порт сервера сессии, отпечаток его сертификата, имя игрока (`auto` — по номеру процесса). После загрузки сейва клиент подключается, тики идут под управлением сервера |
| `ticks` | длительность прогона, по умолчанию 10000 |
| `trace` | `0` — не писать трассировку `Rand` (файл около 19 МБ) |
| `quit` | `1` — закрыть игру после прогона |
| `tpf` | в сессии: не больше стольких тиков за кадр (`0` — как обычно). В `run-tst014.ps1` — `-Tpf 1,30` (c1, c2); там же `-Trace`, `-DenseFrom`/`-DenseTo`, `-Camera 0` |

Прогон без сервера (очередь сценариев, своя папка данных, перезапуск игры между прогонами): `powershell -ExecutionPolicy Bypass -File tools\run-offline.ps1 -Queue raid,raid -Ticks 8000 -Name tst018 -Camera`. Скрипт ждёт строку `queue: finished`, результаты — `RWMLWC/<Name>/` в данных игры.

Оба скрипта требуют запущенного Steam (иначе игра не видит Harmony из мастерской и сбрасывает список модов) и включают в копии настроек «Работать в фоновом режиме». Тестовые экземпляры идут без звука. Окна открываются на мониторе из переменной `RWMLWC_TEST_MONITOR` (`tools/TestWindow.ps1`), запускаются через `tools/StartQuiet.ps1`: игра при создании окна делает его активным, а скрипт сразу возвращает фокус в окно, где был человек (в конце пишет, сколько раз). Человек может в это время пользоваться компьютером.

Ход прогона и ошибки сценариев пишутся в `RWMLWC/automation-log.txt`.

Сценарии и что они проверяют:

- `snap-save` против `none` → совпадают: снятие снимка (сохранение игры) не влияет на симуляцию.
- `snap-reload` против `none` → совпадают: игра, загруженная из снимка, продолжается так же, как игра без перерыва (TST-030). Запись после загрузки продолжается в тот же файл хешей.
- `raid` дважды → файлы хешей совпадают: бой, генерация пешек, стрельба детерминированы.
- `twomaps` дважды → совпадают хеши обеих карт: генерация карты и две карты одновременно.
- `twomaps-freeze` против `twomaps` → хеши первой карты совпадают: заморозка второй карты не влияет на первую (TST-005, часть Б). Хеш замороженной карты не меняется со временем.

## TST-010: порядок проверки

Цель: два запуска одного сейва дают одинаковые хеши состояния 10 000 тиков подряд.

## TST-058: выделенный сервер

1. `dotnet test` — `DedicatedServerTests`, `ConnectionCodeTests`.
2. Сохранение копии: `tools
un-tst014.ps1 -Clients 2 -Scenario join -Name tst058a`. В логе сервера должна быть строка `сохранена копия мира …`.
3. Мир с сервера: запустить `RWMLWC.Server.dll --port 0 --data <папка server из шага 2>` и один экземпляр игры без сейва с меткой `save=` (пусто), `server=…`, `thumbprint=…`, `connectdelay=15`. Ожидание: `Welcome … serverTick=<тик копии> … requesting world snapshot` → `snapshot … received` → `snapshot loaded` → прогон до конца. В логе сервера — `игроку 1 отдан мир с сервера`.
4. Вручную: главное меню → «Сетевая игра» → три варианта; «Создать игру» → выбрать сейв → после загрузки сессия открыта (строка «игрок 1, в сети 1»).

## TST-070: переподключение после обрыва

Свой выделенный сервер (`RWMLWC.Server.dll --port 0`), его консоль через ~100 с выполняет `kick 2`. Два экземпляра игры с меткой: `save=tst`, `server=…`, `thumbprint=…`, `name=c1`/`c2`, `holdsec=40`, `reconnecttest=1`, `ticks=8000`.

Ожидание: у выкинутого — `connection closed` → через 3 с `reconnect: connecting again` → `Welcome … requesting world snapshot` → `snapshot loaded`; на сервере — «вернулся игрок 2», «общий снимок … отдаёт игрок 1», оба применили снимок; до конца прогона сервер не сообщает о расхождении. Вручную: после обрыва без автопрогона появляется окно «Связь с сессией потеряна» с кнопкой «Переподключиться».
